# 贡献工作流的环境准备

仅在 [SKILL.md](SKILL.md) 第 1 节判定需要准备或修复环境时读取本文件；已有可用记忆时跳过。读取后只执行缺失、待处理或受变化影响的部分，不重新检查全部环境。先保留用户已提供的修改需求及现有记录，避免重复输入。

沿用 SKILL.md 的提交边界：环境准备不等于正文修订授权；普通贡献者走 fork，已验证且有写权限的 Collaborator 可使用允许的上游分支，任何身份均不得更改 `release`。

## 按需验证身份和工具

首次验证身份时，通过 GitHub CLI、连接器或 API 的只读仓库权限／协作者信息确认登录用户与写权限，不凭 remote 或口头声明推断。已有对应的已验证记忆时可复用；账号、认证方式或权限发生变化时，失效相关身份／权限记录并定向复查。无法验证上游写权限时使用普通贡献者的 fork 路径。

用户已经给出的改前文字和期望改法应保留，不让用户重复输入。初次环境准备仍在正文核查前完成；后续会话通过读取记忆满足这一步，无需重复检查。以下检查表只用于 SKILL.md 第 1 节触发的按需检查，不用于每次启动时例行复查。

以下任一主路径可用即可，无需同时配置两套工具：

| 主路径 | 环境检查与就绪条件 |
| --- | --- |
| 本地 Git／gh CLI | 检查 `git --version`，有 `gh` 时检查 `gh --version` 和 `gh auth status`；若仓库已在本地，检查 `git status --short`、当前分支和 remotes。Git 与所需 GitHub 认证可用即可沿用本地路径；没有 `gh` 不强制安装，可使用已有 SSH／HTTPS 认证和浏览器完成 fork／PR。 |
| GitHub 连接器 | 从实际工具发现能力，通过只读接口核实登录用户及上游访问；确认可写入完整文件，并具备选定路径所需的分支创建及 PR 能力，且满足以下其一：**具有 fork 功能、当前用户已有可用的上游 fork，或已验证为有写权限的上游 Collaborator 并能写入允许的上游分支**。Collaborator 采用上游提交路径时无需 fork 功能，直接提交 `main` 时也不要求创建分支或 PR 的能力。满足这些条件即可使用连接器路径，无需安装 Git／gh。 |

优先沿用记忆中标为可用的方式；没有相应记录时，优先使用已认证且满足上述条件的连接器，否则使用可用的本地 Git。不能仅凭连接器已安装或能读取公开仓库就声称环境已就绪，也不能假定同名连接器具备相同接口。实际操作正常时不另做权限探测；若获准写入时被拒，更新权限记忆并定向处理，不为测试权限提前提交正文。

**有 Git 不代表已登录 GitHub，也不代表有推送权限。** 本地路径缺少认证时只补齐认证；缺少提交姓名或邮箱时请用户提供，仅设置本仓库的 Git 配置，不擅自修改全局身份。

### 两条路径均不可用：先安装连接器，再重启或新开会话

1. 优先指导用户在**当前 Agent 产品**中安装或启用 GitHub 连接器。使用产品现有的插件发现或安装能力；不知道入口时只询问产品名称，不编造菜单路径。不先要求非开发用户安装 Git 和 gh。
2. 安装或启用后，明确要求用户**重启 Agent，或发起新的会话**，让连接器工具重新加载。在此处保留进度并等待，不假定安装后当前会话立即获得工具，也不继续进入修订或提交步骤。
3. 重启／新会话前保存非敏感进度；无法持久化时，给用户一段可粘贴的恢复摘要，包含本技能路径、上游仓库、待验证的连接器状态，以及用户已提供的修改需求。新会话先读取记忆，只通过实际工具验证待确认的连接器是否已加载，写回结果后继续，不从全套环境检查重新开始。
4. 按当前缺口引导登录和授权。没有 GitHub 账号时，指导前往 <https://github.com/signup> 注册并完成验证；已有账号时登录并完成连接器授权。密码、验证码和授权均由用户自行操作，不在聊天中索要密码或 Token。若安装过程要求先登录，则在该环节完成。
5. 只有连接器确实不受支持，或用户明确选择本地工具时，再指导安装 Git、完成 GitHub 认证；`gh` 按需使用。已有本地路径可用时不额外要求安装连接器。

每次环境核查及安装、重启、登录、授权、切换工具或账号、创建 fork 等环境变更后，都必须立即更新下文规定的环境记忆。待用户操作时先写入待处理状态；用户完成后只验证该项并写回结果。一次只给出当前需要的操作；用户完成后复查一次。仍失败时说明具体阻塞项与下一步，保留进度并等待，不循环要求注册、登录、安装或扩大权限。用户明确只要求本地修订时，只补齐本地编辑所需环境，不强制注册 GitHub 或配置远程权限。

### 普通贡献者只有连接器且没有 fork 功能：引导用户网页 fork

先判断是否为已验证且有写权限的 Collaborator：若是且采用上游提交路径，跳过 fork 准备。其余用户没有 Git／gh，但连接器能读取和写入贡献所需文件、能创建分支及 PR，只是不能创建 fork 时：

- 优先复用记忆中已验证的 fork；没有相关记录或访问异常时，才检查当前登录用户是否已有属于该上游的 fork；有则核实 fork 关系和连接器访问范围并复用，环境可继续，无需重复 fork 或安装本地工具。
- 没有 fork 时，明确说明需由用户通过网页创建。引导用户打开 <https://github.com/QriDoki/in-search-of-lost-time-translation-project>，登录后点击 **Fork**，选择自己的账号并完成 **Create fork**。未注册时先完成注册与验证。
- 请用户提供创建后的 fork 地址，或通过只读接口发现该 fork；核实所有者为当前用户、上游关系正确且连接器能够访问。连接器访问范围若未包含新 fork，只引导补充该仓库的必要授权，再复查。
- fork 就绪后记录地址，继续正文核查；贡献分支、正文写入和 PR 仍等待[SKILL.md](SKILL.md) 第 5 节的修订确认。网页 fork 属于环境准备，不代表用户已经同意任何正文修订。

连接器还缺少文件写入、创建分支或 PR 等能力时，如实说明具体缺口，使用可用的浏览器或用户操作补齐；无法补齐则保留进度并报告阻塞，不能仅因已有 fork 就宣称能完成贡献。

## 必须保存环境核查与后续变更

**环境核查结果及后续环境变更必须写入记忆，不能只在回复中说明。** 以“本项目 + 当前用户 + 当前环境”为作用域保存非敏感记忆。优先使用 Agent 的持久记忆；无此能力但能写本地文件时，使用项目根下的 `work/contribute-memory.md`。本仓库已忽略 `work/`，不要将记忆文件加入提交。两种持久化方式都不可用时，明确说明只能在当前会话记住，并向用户提供可在下次粘贴的简短摘要。

每次启动主动读取记忆；有可用记录时直接复用，不做例行环境复查。首次核查、核查失败、配置进行中、变更完成以及实际操作暴露状态变化时，都须及时写回实际状态、依据和下一步。只保留最新配置及必要的变更摘要，无需积累完整命令日志。

记录更新包括：工具安装／移除／启用、连接器能力变化、等待重启及加载结果、注册／登录／退出／切换账号、授权及 Collaborator 权限变化、认证失败与恢复、fork 创建或失效、路径／remote／提交方式变化。账号或认证上下文改变时，相关权限及 fork 访问状态标为待验证，不能继承其他身份的写权限。仅用户声称已完成的步骤先记为待验证，验证成功后再改为可用。

不能持久保存时须明确说明，并提供恢复摘要；后续用户粘贴摘要后按记录继续，不宣称已经写入持久记忆。记忆用于复用环境配置，具体正文修订及目标仓库／分支的确认仍按 [SKILL.md](SKILL.md) 第 5 节执行。

记录以下字段即可：

```text
上游：QriDoki/in-search-of-lost-time-translation-project
环境标识：Agent 产品／本地环境的非敏感标识
使用方式：github-connector 或 local-git
工具及能力：Git／gh 是否可用、连接器名称及已验证的分支／文件／PR 能力
GitHub 用户名：实际验证的登录名
认证方式：连接器 / SSH / HTTPS / gh（只记录类型）
本地仓库路径：如有
fork：实际 fork 的 owner/repo，如已创建
上游身份及权限：Collaborator（具有写权限）/ 普通贡献者 / 待验证，以及验证日期
提交路径：fork + PR / 上游新建分支 / 上游 main
提交边界：只改 polish/dev/；禁止更改 release 分支
连接器 fork 能力：支持 / 不支持 / 待验证
状态：可用 / 待重启或新会话 / 待登录 / 待授权 / 待网页 fork / 待验证 / 不可用
最近核查或变更：时间、受影响项、实际结果及依据
待处理步骤：当前阻塞项、用户下一步、恢复时仅需验证的项目
进行中任务：上游基线提交、目标目录 polish/dev、目标仓库与分支、提交链接或 PR 链接（如有）
```

不记录密码、Token、私钥、Cookie 或带凭据的 URL。恢复进行中的同一任务时沿用分支和 `polish/dev`，不重复复制、重复 fork 或重复创建 PR。旧记忆若要求创建时间戳版本或一律禁止 Collaborator 写上游，以本指南当前规则为准；已验证的 Collaborator 身份和写权限可按 [SKILL.md](SKILL.md) 第 1 节复用；没有验证依据或相关环境变化时才定向复查。
