## 行内注释语法（Inline Annotation）

在 Markdown 基础上扩展自定义行内注释语法，用于文学翻译、译者注及文本校勘。

### 1. 有锚点注释

**语法：**

```
⊂被标注文本⊃≼类型emoji序列注释内容≽
```

**示例：**

```
⊂教义⊃≼🔤原文 Credo，本为基督教信经；教义、正统、信徒、异端这套宗教词汇贯穿对小圈子的描写。≽
```

- `⊂...⊃`：定义注释锚点，即被注释的文本范围。
- `≼...≽`：定义注释内容。
- `≼` 后紧接表示注解类型的一个或多个 emoji，多个 emoji 连续书写，再直接接注释正文，不插入空格。
- 注释与锚点直接关联，不允许在两者之间插入其他字符。

### 2. 无锚点注释

**语法：**

```
≼类型emoji序列注释内容≽
```

**示例：**

```
他说：“你好”≼🔤这里的人物正在使用法语交谈≽。
```

- 注释不绑定特定文本范围。
- 注释位置由其在正文中的插入位置决定。

### 3. 注解类型

有锚点和无锚点注释均须按内容分类，在 `≼` 后添加对应的一个或多个 emoji。涉及多个类型时，连续列出所有适用类型，不插入空格，不重复同一类型。

例如：`⊂教义⊃≼🔤🏛️原文 Credo，本为基督教信经，此处借用宗教词汇描写小圈子。≽`。

Vite 阅读页面不显示这些类型前缀 emoji。读者可在“字体设置”的“注解类型”多选下拉菜单中选择显示的类型；一个注解有多个类型时，只要其中一个类型被选中就显示。默认不显示 ⚖️、🧵、🧩，其余类型默认显示。选择与字体设置一同保存在当前浏览器的本地存储中；恢复默认设置时也恢复默认类型选择。未带类型前缀的旧注解继续显示。隐藏注解时仍保留被标注的正文。

| 类型 | 主要内容 | 例子 | Emoji |
|---|---|---|---|
| **人物与文化背景** | 人名、地名、历史事件、社会习俗、宗教、阶层制度 | 某位贵族是谁；一种沙龙礼仪有什么含义 | 🏛️ |
| **典故与互文** | 文学、艺术、音乐作品的引用、影射或化用 | 一句话暗引《圣经》；某个比喻来自一幅画 | 📚 |
| **词义与措辞** | 多义词、语体、语气，以及中文选词的取舍 | 为什么译成“眷恋”而不是“怀念” | 🔤 |
| **句法与行文** | 长句结构、指代关系、时态，以及拆句、语序与节奏的处理 | 一个插入语修饰谁；为什么保留长句 | 🧩 |
| **双关与文字游戏** | 谐音、歧义、词形呼应、姓名游戏及其翻译补偿 | 原文同时包含两层意思，中文如何兼顾 | 🎭 |
| **修辞与文体** | 隐喻、反讽、夸张、拟人、声音效果，以及人物说话方式 | 看似赞美实为讽刺；某个人物刻意使用俗语 | 🪶 |
| **叙事与主题关联** | 伏笔、前后照应、反复意象、视角变化、主题线索 | 此处的花与后文再次出现的花形成呼应 | 🧵 |
| **版本与译法比较** | 原文版本差异、异文、已有译本的处理与争议 | 不同版本标点不同；几种译法各自强调什么 | ⚖️ |

### 4. 通用规则

1. 注释必须位于同一行内，不允许跨行。
2. 注释内容可以包含空格及普通标点。
3. 不允许注释嵌套。
4. 特殊符号 `⊂`、`⊃`、`≼`、`≽` 如需作为普通文本使用，应以反斜杠 `\` 转义。
5. 注释作为独立的语义结构保存，渲染器可将其展示为行内小字、弹出式注释或其他形式。
6. 导出纯文本时，可以选择保留或移除注释；有锚点注释移除标记后仍保留被标注文本。

### 5. 形式文法

```
annotation        = anchored | unanchored ;
anchored          = "⊂", text, "⊃", "≼", categories, note, "≽" ;
unanchored        = "≼", categories, note, "≽" ;
categories        = category, { category } ;
category          = "🏛️" | "📚" | "🔤" | "🧩" | "🎭" | "🪶" | "🧵" | "⚖️" ;
```

其中 `categories` 表示一个或多个连续的注解类型 emoji，`category` 表示单个类型 emoji，`text` 表示非空被标注文本，`note` 表示不含类型 emoji 前缀的非空注释正文。`text` 和 `note` 均遵循上述转义和禁止嵌套规则。

**注意：** 此语法是自定义 Markdown 扩展，不属于 CommonMark 标准，需要专门的解析器或预处理器支持。
